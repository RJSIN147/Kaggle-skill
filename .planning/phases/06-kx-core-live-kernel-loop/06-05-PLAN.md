## Phase Goal

**As a** Kaggle competitor, **I want to** go from an empty folder to a recorded experiment through one `kx` CLI that runs my idea on a Kaggle script kernel by default, **so that** the core loop (idea, kernel run, machine-checked score, verdict, ledger, strategy) works live on the v2 foundations.

**This slice:** the user (the AI) declares an idea with `kx new`, sees what was already tried, writes the CV scheme
and model in the AI block of a ready-to-push script, and records why that CV scheme fits — all validated before
anything can be pushed.

<objective>
Deliver `kx new`: experiment.json + its stdlib validator, the tabular script-kernel template with an AI-written CV
scheme, and the one standard OOF/test prediction format with its validator.

Purpose: CORE-03 (experiment declared in experiment.json, validated, invalid refused before any push — the refusal
itself is wired into `kx run` in 06-07), TMPL-01 (tabular template, AI-written CV code, reasoning recorded),
ENS-01 (kx-preds/1 written by the template and checked by the validator the recorder uses in 06-07).
Discretion choices adopted from RESEARCH: stdlib validator with strict keys; CSV `kx-preds/1`; the optional harness
hardening (protected_sha256 over everything outside the AI block, so the AI cannot edit the scorer); n_folds fixed
at mint time (`kx new --n-folds`, default 5) and rendered into the protected header. RESEARCH Open Question 2
adopted: the harness writes the Kaggle image's python/pandas/numpy/scikit-learn/lightgbm versions into
kx_manifest.json so the first live run (06-07) records them.

Output: `src/kx/{preds,experiment}.py`, `src/kx/templates/tabular/train.py.tmpl`, `src/kx/commands/new.py`, tests,
and the optional template-test harness test.
</objective>
