## Phase Goal

**As a** Kaggle competitor, **I want to** go from an empty folder to a recorded experiment through one `kx` CLI that runs my idea on a Kaggle script kernel by default, **so that** the core loop (idea, kernel run, machine-checked score, verdict, ledger, strategy) works live on the v2 foundations.

**This slice:** the user runs `kx run exp-001` and their idea executes on a private Kaggle CPU script kernel with
internet off; kx waits within a bound, pulls the outputs safely and records a machine-checked CV score, then the
verdict and `kx strategy` close the cycle — live on Titanic (ROADMAP success criterion 4).

<objective>
Deliver `kx run`: validate -> build script metadata -> commit the exact code -> push via the in-process SDK with
read-back -> bounded poll with resume -> safe pull -> fail-closed record (v1 ladder + kx-preds/1 rung) -> ledger.
Prove the whole core-value cycle live on Titanic.

Purpose: RUN-01 (private script kernel, internet off by default, bounded poll, pull, record, no conversion),
CORE-04 (fail-closed contract and ledger unchanged under kx), CORE-03 (invalid spec refused before any push),
TMPL-01/ENS-01 proven live. Adopted RESEARCH recommendations: v1 terminal set (CANCEL_REQUESTED stays in-flight,
Open Question 4), `--wait` default 90 s sized under the 120 s Bash tool timeout, kernel slug
`kx-<slug>-<workspace_id>-<exp_id>` (<= 50 chars) so two workspaces never version each other's kernel, pull into
output/ via our own safe-path loop (kaggle 2.2.3's kernels_output is not traversal-safe), version read back and never
guessed, and an empty-listing retry (A2).

Output: `src/kx/{kernel,record}.py`, `src/kx/commands/run.py`, five adapter methods, unit tests, a live Titanic cycle
test, and the first real script-kernel log captured as a fixture.
</objective>
